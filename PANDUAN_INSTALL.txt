SIRUKUN 1.0 - PANDUAN SETUP DATABASE DAN AKUN
==============================================

1. PERSYARATAN
- PHP 8.2 atau lebih baru dan MySQL/MariaDB. XAMPP dapat digunakan, tetapi
  folder proyek tidak wajib berada di htdocs.
- Ekstensi PHP: pdo_mysql, mbstring, openssl, fileinfo, ctype, tokenizer,
  dom, xml, xmlwriter, gd, dan zip.
- Composer untuk memasang vendor bila folder vendor belum tersedia.
- Node.js/npm tidak diperlukan.
- Jangan menghapus folder vendor, storage, bootstrap/cache, atau file .htaccess.

2. PERSIAPAN DATABASE DAN AKUN AWAL
1) Jalankan MySQL/MariaDB. Buat database kosong bernama sirukun_apps
   melalui phpMyAdmin atau MySQL. Siapkan pengguna database dengan hak
   membuat tabel dan indeks pada database tersebut.
2) Dari terminal, masuk ke folder proyek. Pasang dependensi jika vendor
   belum tersedia:
   composer install
3) Salin .env.example menjadi .env. Atur DB_HOST, DB_PORT,
   DB_DATABASE=sirukun_apps, DB_USERNAME, DB_PASSWORD, dan APP_URL.
4) Jalankan perintah berikut menggunakan PHP yang sama dengan server:
   php artisan optimize:clear
   php artisan key:generate
   php artisan migrate --seed
5) Mulai server lokal dari folder proyek:
   php artisan serve
   Untuk XAMPP, dapat gunakan:
   C:\xampp\php\php.exe artisan serve
6) Buka pada komputer yang sama:
   http://127.0.0.1:8000/install.php
7) Isi identitas RW awal (kode, nama lingkungan, kelurahan, nomor RT),
   lalu buat akun Administrator. Pendaftaran dibatasi ke komputer server
   dan otomatis dikunci setelah berhasil. Kata sandi Administrator minimal
   6 karakter. Semua kata sandi menggunakan batas minimal ini. Huruf, angka,
   simbol, dan spasi diperbolehkan; huruf besar
   dan kecil dibedakan.
8) Masuk melalui http://127.0.0.1:8000/. Tambahkan RW/RT lain bila
   diperlukan, lalu lengkapi hunian dan data warga.

Tidak ada akun Administrator atau kata sandi bawaan. File install.php tidak
membuat database dan tidak menjalankan migrasi; kedua tahap tersebut dilakukan
secara eksplisit melalui MySQL dan perintah Artisan di atas. Jangan gunakan
database berisi data aplikasi lain.

3. PENGATURAN AWAL SETELAH MASUK
Urutan yang disarankan:
1) Wilayah RT/RW: lengkapi data wilayah dan tambahkan RT yang dibutuhkan.
2) Data hunian: buat alamat rumah, kontrakan, atau indekos di RT terkait.
3) Kartu keluarga: buat nomor KK dan hubungkan ke hunian.
4) Data warga: buat kepala keluarga terlebih dahulu, kemudian anggota.
   NIK dan nomor KK berupa 16 digit. Bayi boleh belum memiliki NIK.
5) Kelola pengguna: buat akun Ketua RT, perangkat RT, Ketua RW,
   Sekretaris RW, serta Warga. Akun Warga dihubungkan ke warga yang terdata.
6) Untuk peran RT, pilih RT dan jabatan. Untuk RW, pilih RW dan jabatan.
   Persetujuan hanya dapat dilakukan akun berjabatan Ketua RT/Ketua RW.
7) Menu aplikasi: atur nama, urutan, status aktif, dan hak menu per peran.
8) Akun pengguna dapat mengganti kata sandi melalui Profil saya.
   Pengaturan ulang kata sandi yang terlupa dilakukan oleh Administrator.

Satu warga dapat memiliki paling banyak satu akun Warga. Akun pengurus
dan akun warga tidak digabung menjadi satu peran. Administrator mempunyai
akses global, tetapi tidak menyamar sebagai Ketua RT/RW saat persetujuan.

4. FITUR YANG TERSEDIA
- Login/logout nyata, kata sandi di-hash, sesi, proteksi CSRF, pembatasan
  percobaan login, serta otorisasi server berdasarkan peran dan wilayah.
- CRUD hunian, KK, warga, wilayah, pengguna, dan menu.
- Pergantian kepala keluarga melalui formulir Ubah kartu keluarga.
- Mutasi masuk, keluar, lahir, meninggal beserta unggahan dokumen privat.
- Laporan Warga berstatus menunggu pencatatan. RT/Administrator memeriksa
  lalu menerapkan mutasi satu kali untuk memperbarui data induk.
- Saat kepala keluarga pindah/meninggal dengan anggota tersisa, pilih
  kepala keluarga pengganti. Jumlah warga/KK dihitung dari data aktif.
- Tamu menginap 1x24 jam: identitas, asal, tujuan, rumah tujuan,
  mulai/rencana selesai, dan pencatatan waktu keluar aktual.
- Kontrakan/indekos: penghuni, periode sewa, dan kontak darurat.
- Pengingat dalam aplikasi: tamu melewati batas dan masa sewa H-7 atau
  yang sudah terlewati. Notifikasi tidak dikirim lewat WhatsApp/SMS/email.
- Lima surat: KTP/KK, SKTM, Domisili, Pengantar Nikah, Keterangan Usaha.
- Alur permohonan -> Ketua RT -> Ketua RW -> PDF bernomor, QR, arsip.
- Keputusan pending/approved, catatan, dan riwayat revisi/persetujuan.
- Nomor surat berurutan per RW/tahun. Dokumen diterbitkan sekali dalam
  transaksi; nomor yang dicabut tidak digunakan kembali.
- PDF asli tersimpan privat. Perubahan master tidak mengubah snapshot
  isi dokumen yang telah terbit. Koreksi surat terbit dilakukan dengan
  pencabutan lalu pengajuan baru.
- Halaman verifikasi QR menampilkan status/nomor/jenis/wilayah dan nama
  tersamar. Surat yang dicabut dinyatakan tidak berlaku.
- Dashboard, grafik mutasi, filter bulan/RT, rekap jenis/status surat,
  ekspor PDF dan spreadsheet Excel .xlsx.
- Log perubahan; penghapusan data bisnis secara soft delete agar riwayat
  dan relasi tetap utuh. Master dengan data anak aktif tidak dihapus
  sebelum data turunannya dipindahkan/dinonaktifkan.
- Backup SQL melalui menu Administrator, beserta jadwal backup harian.

Nama pengesah pada PDF merekam persetujuan sistem. Ini bukan tanda tangan
elektronik tersertifikasi. Jika kelurahan mensyaratkan tanda tangan basah,
surat dapat dicetak dan ditandatangani sesuai prosedur setempat.

5. URL QR DAN PENGGUNAAN DARI PONSEL
- QR memuat URL absolut dari APP_URL pada .env ketika surat diterbitkan.
- localhost pada ponsel berarti ponsel itu sendiri, bukan komputer XAMPP.
- Untuk LAN, ubah APP_URL menjadi alamat komputer yang dapat dijangkau,
  misalnya http://192.168.1.10/sirukun/public. Angka IP hanya contoh.
- Buka alamat yang sama pada komputer dan ponsel di jaringan yang sama.
  Sesuaikan izin firewall Apache bila diperlukan.
- Surat yang sudah diterbitkan tetap memuat URL lama. Pertahankan alamat
  tersebut atau sediakan pengalihan ketika memindahkan server.
- APP_DEBUG harus tetap false saat digunakan menyimpan data warga.

6. AKTIFKAN PENGINGAT DAN BACKUP TERJADWAL
Sistem juga memeriksa pengingat saat dashboard dibuka. Untuk menjalankan
jadwal otomatis walaupun dashboard tidak dibuka:
1) Buka Windows Task Scheduler -> Create Task.
2) Beri nama SIRUKUN Scheduler.
3) Trigger: setiap hari, ulangi setiap 1 menit, durasi indefinitely.
4) Action: Start a program.
   Program: C:\xampp\htdocs\sirukun\scheduler.bat
   Start in: C:\xampp\htdocs\sirukun
5) Simpan task; komputer dan layanan MySQL harus hidup.
6) Jika lokasi XAMPP berbeda, periksa SIRUKUN_PHP pada scheduler.bat.

Scheduler memeriksa notifikasi tiap 5 menit dan backup database pukul 01.00
zona Asia/Jakarta. Catatan proses: storage\logs\scheduler.log.
CLI alternatif:
C:\xampp\php\php.exe artisan sirukun:reminders
C:\xampp\php\php.exe artisan sirukun:backup

7. BACKUP DAN PEMULIHAN
- Menu Pencadangan menghasilkan SQL database dan checksum SHA-256.
- Unduh SQL ke perangkat/penyimpanan terpisah.
- Backup SQL TIDAK menyertakan foto, PDF, maupun file konfigurasi.
- Salin juga storage\app\private dan .env secara terpisah dengan akses
  terbatas, karena berisi dokumen pribadi dan konfigurasi aplikasi.
- Untuk pemulihan, buat database kosong melalui phpMyAdmin lalu impor
  berkas SQL. Jangan mengimpor ke database berisi data lain: SQL backup
  memuat perintah DROP TABLE untuk pemulihan penuh.
- Salin kembali folder dokumen, konfigurasi .env, dan installed.lock
  dari instalasi yang dipulihkan; periksa DB_HOST/PORT/NAME/USER/PASSWORD.
- APP_KEY harus dipertahankan. Pengguna perlu masuk ulang setelah pindah.
- Simpan folder aplikasi versi yang sama dengan backup yang dipulihkan.

8. PENANGANAN MASALAH
- Halaman kosong/500: periksa storage\logs\laravel.log, versi PHP,
  kelengkapan vendor, serta hak tulis storage dan bootstrap\cache.
- Ekstensi belum aktif: buka C:\xampp\php\php.ini, aktifkan ekstensi
  yang disebut installer, lalu restart Apache. Contoh extension=gd,
  extension=zip, extension=pdo_mysql, extension=mbstring.
- URL selain halaman awal 404: pastikan mod_rewrite aktif dan konfigurasi
  Directory htdocs menggunakan AllowOverride All; restart Apache.
- Akses ditolak saat memakai /sirukun/app atau /sirukun/.env adalah benar:
  file sumber/config/storage tidak boleh diakses lewat web. Gunakan /public/.
- Database gagal terhubung: periksa MySQL sudah Start, port, pengguna,
  dan kata sandi. Port MySQL bukan port Apache.
- Migrasi gagal: periksa kredensial database dan storage\logs\laravel.log.
  Periksa status dengan php artisan migrate:status; jangan menghapus atau
  mengganti database sebelum memastikan tidak ada data yang perlu disimpan.
- Installer terkunci setelah berhasil: perilaku normal. Jangan menghapus
  storage\app\installed.lock pada instalasi yang sudah berisi data.
- Unggahan ditolak: hanya JPG/PNG/PDF maksimal 2 MB per berkas. Pastikan
  post_max_size dan upload_max_filesize pada php.ini mencukupi.
- Surat pending RT/RW belum bisa diunduh: tunggu persetujuan sesuai tahap.
- Akun Sekretaris/Perangkat tidak dapat mengesahkan: hanya jabatan Ketua
  yang berwenang mengesahkan tahap masing-masing.
- RT tidak melihat data RT lain: pembatasan wilayah memang diterapkan.
- Tidak dapat mengganti kepala keluarga langsung di Data warga: gunakan
  Ubah kartu keluarga -> Ganti kepala keluarga agar perubahan atomik.
- Cache konfigurasi setelah mengubah .env: dari folder aplikasi jalankan
  C:\xampp\php\php.exe artisan optimize:clear

9. STRUKTUR PROYEK
app/Http/Controllers : proses HTTP dan validasi layanan
app/Http/Middleware  : pemeriksaan peran dan header keamanan
app/Models           : model autentikasi pengguna/peran
app/Services         : akses wilayah, audit, berkas, surat, laporan, backup
bootstrap/           : inisialisasi Laravel
config/              : konfigurasi aplikasi
database/migrations/ : struktur 25 tabel bisnis
database/seeders/    : peran, menu, jenis surat dasar
public/              : satu-satunya direktori yang dilayani web
public/install.php   : installer localhost, otomatis terkunci setelah sukses
public/assets/       : CSS/JavaScript lokal; tanpa CDN
resources/views/     : tampilan Blade dan template PDF
routes/              : rute web dan scheduler
storage/             : sesi, log, cache, PDF/unggahan privat, backup
tests/               : pengujian aplikasi; tidak diakses melalui web
vendor/              : dependensi siap pakai
scheduler.bat        : penghubung Windows Task Scheduler

10. BATAS VERIFIKASI
Pengujian dilakukan pada PHP 8.3 dan MariaDB 10.11, termasuk instalasi baru
melalui HTTP, sesi login, CSRF, backup/restore SQL, PDF/QR, dan Excel.
Dependensi dikunci untuk kompatibilitas PHP 8.2. Paket belum dijalankan
langsung pada Windows/XAMPP milik pengguna. Lihat HASIL_PENGUJIAN.txt.
